# naming

## 手順

1. 名前を付ける階層を決める。造語を作るのは会社名と看板プロダクトだけ。それ以外は説明で通す。
2. 伝えたい便益を1方向に絞る。速さなのか、堅さなのか、適合なのか。
3. その方向を向く既存語を3語選ぶ。共通の音や綴りを持つ組み合わせを探す。
4. 共通部分で圧縮して造語にする。頭と尾を組み合わせる。
5. 2音節以内、綴りが一意、全小文字で自然、という条件で削る。
6. `<造語> + <普通名詞>` が読めるか試す。
7. 名前空間の空きを確認する。
8. 商標を確認する。これは別工程で、命名の中で済ませない。

## 造語は一つだけ

固有名を作るのは最上位の1語に限る。その下の機能名は、ひねらず説明にする。

- 良い例。Instant Rollback、Image Optimization、Bot Management、Rolling Releases。名前ではなく説明。
- 悪い例。機能ごとに造語を作り、利用者に覚える単語を配り続ける。

ブランドの予算を1語に集中させ、下位では検索性と自明さを取る。命名の失敗の多くは、機能にまで固有名を付けることで起きる。

## 語根の選び方

同一方向を向く既存語を3語。無意味な音の羅列から作らない。

Vercel の例。versatile、accelerate、excel。3語とも「速く、うまく、柔軟に」を向き、ver と cel を共有する。VER + CEL。頭を1語から、尾を別の語から取っている。

条件は3つ。

- 3語が同じ方向を向いていること。方向が割れると意味が濁る。
- 音か綴りを共有していること。共有部分が圧縮の接合点になる。
- 語根が製品の機能そのものを指していること。比喩から始めない。

## 削る条件

- 2音節以内。3音節になったら語根を選び直す。
- 綴りが一意。読み方が割れるものは落とす。
- 全小文字で自然に見えること。ハイフンもドットも要らないこと。
- タイプしやすいこと。CLI やパッケージ名がそのまま看板になる領域では、名前は音である前に文字列。

## 意味は主張せず含意する

FastDeploy のような直接記述は、意味が固定されて成長を妨げる。語根を潜ませるだけにする。誰も Vercel から versatile を復元しないが、それでよい。初見で方向が感じられれば足りる。

事業が変わっても名前が古びないかを試す。今の説明文を外して、3年後の事業に載せ替えても成立するか。

## 実在語と借用語を避ける

中心に据える名前は造語にする。

- 実在語は商標が弱い。既に他分野で使われている。
- 借用語は発音が割れる。意味が既に固定されている。
- 別の分野で確立した用語と衝突する。インフラ領域で Raft、Plex、Corda などを選ぶと、既存プロダクトの記憶に飲まれる。
- 語義に負の含みがないか確認する。地域と言語ごとに変わる。

借用語は捨てるのではなく配置し直す。中心には向かないが、デザインシステム名やライブラリ名のような周辺資産には向く。Vercel が Zeit を捨てて Geist と Satori を残したのはこの形。

## 拡張できるか

`<造語> + <普通名詞>` を声に出す。Vercel Functions、Vercel Sandbox は読める。造語と普通名詞の係り受けが破綻するなら、その名前は拡張できない。

Zeit の製品名が Now だった例が失敗の型。Now は普通名詞すぎて検索も商標も成立せず、Zeit Now は借用語と普通名詞の並びで係り受けが読めない。

語根を一つ作ったら、派生させて系列にする。Turborepo と Turbopack は turbo- を共有する。毎回新しい造語を作らない。

## 隣接ブランドとの衝突

語頭や語形が、参照した既存ブランドに近づいていないか確認する。良い名前を分析した直後は、その音に引きずられる。派生ブランドに見えたらその案は捨てる。

## 空きの確認

```sh
curl -sS -o /dev/null -w '%{http_code}\n' https://registry.npmjs.org/<name>   # 404 なら空き
curl -sS -o /dev/null -w '%{http_code}\n' https://github.com/<name>           # 404 なら空き
curl -sS -o /dev/null -w '%{http_code}\n' https://crates.io/api/v1/crates/<name>
```

- ドメイン、npm、GitHub の org、主要レジストリを見る。
- 完全一致だけでなく、1文字違いの既存プロダクトも探す。
- 空いていることと、使ってよいことは別。商標調査は必ず別に行う。

## 確定前に確認する

- 造語を作った箇所が、会社名か看板プロダクトに限られているか。機能に固有名を配っていないか。
- 語根3語が同じ方向を向き、共通音を持っているか。
- 2音節以内か。
- 綴りが一意で、読み方が割れないか。
- 全小文字でタイプでき、ハイフンやドットが要らないか。
- 便益を名指しせず含意しているか。3年後の事業でも成立するか。
- `<名前> + <普通名詞>` が読めるか。
- 実在語や借用語を中心に据えていないか。
- 参照したブランドに寄っていないか。
- npm、GitHub、ドメインの空きを確認したか。
- 商標調査を別工程として計画したか。
